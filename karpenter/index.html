    Karpenter / AutoNode¶

    AutoNode is ROSA HCP's offering of Karpenter — a Kubernetes autoscaler that dynamically provisions EC2 instances in response to unschedulable pods. Unlike the default Cluster Autoscaler (which scales predefined MachinePools), Karpenter selects instance types based on workload requirements at scheduling time.

    AutoNode is a day-2 feature that customers enable on an existing cluster. It can coexist with OCM-managed MachinePools.

    Custom Resources¶

    OpenshiftEC2NodeClass (customer-facing)¶

    This is what customers configure. It exposes only the fields customers are permitted to set:

    • subnetSelectorTerms — which subnets to launch into
    • securityGroupSelectorTerms — which security groups to attach
    • Tags, EBS volume configuration, KMS encryption

    The karpenter-operator reconciles each OpenshiftEC2NodeClass into a corresponding EC2NodeClass, merging in platform defaults: - AMI selection (Red Hat managed, RHCOS) - Instance profile (worker IAM role) - Metadata options (IMDSv2 required)

    A default OpenshiftEC2NodeClass is auto-created when AutoNode is enabled. Customers can create additional ones.

    VAP Protection

    A Validating Admission Policy (VAP) blocks direct edits to EC2NodeClass objects — customers must use OpenshiftEC2NodeClass instead.

    NodePool¶

    Defines provisioning constraints: - Instance types, capacity type (on-demand/spot), AZs - Labels, taints, disruption policies - References an EC2NodeClass via nodeClassRef

    NodeClaim¶

    Karpenter's internal representation of a requested node. Created automatically when pods are unschedulable. No retry limit — Karpenter keeps creating NodeClaims until the issue resolves or the NodePool reports NoCompatibleInstanceTypes.

    How Autoscaling Works¶

    sequenceDiagram
    participant POD as Unschedulable Pod
    participant KC as Karpenter Controller
    participant AWS as AWS EC2
    participant NODE as New Worker Node

    POD->>KC: kube-scheduler marks pod Unschedulable
    KC->>KC: Simulate scheduling, find best instance type
    KC->>AWS: Launch EC2 instance (NodeClaim)
    AWS-->>NODE: Instance boots, joins cluster
    NODE-->>POD: Pod schedules successfully
    Note over KC: NodeClaim → Node (Ready)

    Karpenter continuously watches for: - Scale-up: Unschedulable pods → provision new nodes - Scale-down: Idle/underutilized nodes → consolidation (terminate and reschedule)

    Guest Cluster Metrics Forwarding (OCP 4.22+)¶

    Starting in OCP 4.22, Karpenter metrics are forwarded to the guest cluster's Prometheus. OCM enables this automatically via the hypershift.openshift.io/enable-metrics-forwarding annotation on the HostedCluster.

    This deploys: - endpoint-resolver and metrics-proxy in the HCP namespace on the MC - metrics-forwarder in the guest cluster (openshift-monitoring)

    Checking AutoNode Status¶

    # Check if AutoNode is enabled on a hosted cluster
oc get hostedcluster -n $HC_NS $CLUSTER_NAME \
  -o jsonpath='{.metadata.annotations.hypershift\.openshift\.io/enable-metrics-forwarding}'

# List OpenshiftEC2NodeClasses (on the hosted cluster)
oc get openshiftec2nodeclass

# List NodePools managed by Karpenter (on the hosted cluster)
oc get nodepools -l "karpenter.sh/managed=true"

# List NodeClaims (shows in-flight node provisioning)
oc get nodeclaims

# Check Karpenter controller logs (on the MC, in HCP namespace)
oc logs -n $HCP_NS deploy/karpenter -f
