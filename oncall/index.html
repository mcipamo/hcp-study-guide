    On-Call Guide (RHOBS Alerts)¶

    This page covers how to respond to ROSA HCP alerts that come through the RHOBS alerting pipeline.

    RHOBS Alert Identification¶

    RHOBS alerts have the prefix [HCP] [RHOBS] in PagerDuty. Every PD incident includes:

    Field Description
    dashboard Grafana link pre-loaded with the cluster's metrics, logs, and probe data
    ocm_link Link to the cluster in OCM console
    link Link to the relevant SOP/runbook
    cluster_id The HCP cluster ID (or MC ID for MC-level alerts)
    firing List of sub-alerts with alertname, cluster_id, namespace, and description

    How RHOBS Alerting Works¶

    Step-by-Step Response¶

    1. Open the dashboard link from the PD incident — opens Grafana with correct datasource, region, and cluster pre-selected
    2. Check the SOP link — follow the linked runbook for the specific alert type
    3. Check OCM via ocm_link — verify cluster state (ready, installing, limited support, etc.)
    4. Investigate in Grafana — Overview → API Server → Logs → Probes

    Probe Architecture¶

    There are three probe sources, each covering different cluster types:

    Common Alert Types¶

    api-ErrorBudgetBurn (Most Common)¶

    The HCP API server availability is below the SLO threshold.

    Triage steps:

    1. Check probe source — the firing alert's namespace tells you:
    2. openshift-route-monitor-operator = RMO (internal, from MC via cluster DNS)
    3. rhobs-production = cell-side agent (external, from RHOBS cell)

    4. rhobs-synthetics-prod-* = backplane agent (private HCPs via PrivateLink/TGW)

    5. Scope the failure — if agent probe fails but RMO passes, check if all private HCPs on the same MC are affected: 

      count by (mc_name) (group by (mc_name, _id) (probe_success{private="true"} == 0))

    6. All clusters on MC failing → infrastructure issue (NLB exhaustion, TGW, PrivateLink)

    7. Only this cluster → per-cluster issue (router, NLB, VPCE for this HCP)

    8. Check probe duration: 

      probe_duration_seconds{private="true", _id="<cluster-id>"}

    9. ~24.5s (timeout): TCP/TLS connection failure — NLB, PrivateLink, or router level
    10. Sub-second with status_code=0: Connection refused — router or NLB rejecting

    11. Sub-second with non-200 status: API server returning errors

    12. Check MC node bandwidth: 

      topk(5, sum by (instance) (rate(node_ethtool_bw_in_allowance_exceeded{}[5m])))
      Elevated values = MC nodes dropping packets due to EC2 bandwidth limits.

    KubeAPIServerDown¶

    No ready KubeAPIServer pods in the HCP namespace.

    • Installing clusters are automatically suppressed
    • Check OCM cluster state first
    • Then check pod status: oc get pods -n $HCP_NS | grep kube-apiserver

    RequestServingNodesNeedUpscale¶

    A request serving node pair has been undersized for 1 hour.

    • Alert description includes node name, MC ID, and HCP cluster name
    • See Node Operations for the resize SOP

    osdctl rhobs Commands¶

    # Setup (~/.config/osdctl)
# rhobs_production_vault_path: "osd-sre/rhobs/sd-sre-prod-creds"
# rhobs_stage_vault_path: "osd-sre/rhobs/sd-sre-stage-creds"

# Query metrics for a cluster
osdctl rhobs metrics -C <cluster-id> -f 'cluster_operator_up{name="ingress"}'

# Query probe metrics
osdctl rhobs metrics -C <cluster-id> -f 'probe_success{probe_url=~".*api.*"}'

# Query logs (requires MC cluster ID)
osdctl rhobs logs -C <mc-cluster-id> -n <hcp-namespace> --since 30m

# Filter by container
osdctl rhobs logs -C <mc-cluster-id> -n <hcp-namespace> -c kube-apiserver --since 1h

# Search for errors
osdctl rhobs logs -C <mc-cluster-id> -n <hcp-namespace> --level error --since 1h

# Stream logs (like kubectl logs -f)
osdctl rhobs logs -C <mc-cluster-id> -n <hcp-namespace> -f

# Find the RHOBS cell for a cluster
osdctl rhobs cell -C <cluster-id>

    Automatic Alert Suppression¶

    Alerts are automatically suppressed for clusters that are:

    • Installing (waiting for initial availability)
    • Deleting
    • In limited support
    • Manually silenced (via HostedCluster label)

    No manual action needed for these states.

    RHOBS Regional Cell Capacity Fleet-wide cell health

    Querying Logs in Loki (Grafana Explore)¶

    Select datasource: rhobs-<region>-<shard>-production-hcp-logs

    # Logs for a specific HCP namespace
{k8s_namespace_name="ocm-production-<hash>-<cluster-name>"}

# Filter by log type
{k8s_namespace_name="ocm-production-<hash>-<cluster-name>", openshift_log_type="infrastructure"}

# Search for errors
{k8s_namespace_name="ocm-production-<hash>-<cluster-name>"} |= "error"

    AI Agent Integration¶

    osdctl rhobs mcp provides an MCP server for Claude Code and other AI agents:

    # One-liner for Claude Code
claude --mcp-config "$(osdctl rhobs mcp config)"

    Available tools: rhobs_metrics, rhobs_logs, rhobs_alerts
