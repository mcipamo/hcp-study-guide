    Zero Egress¶

    Zero Egress (ZE) clusters are ROSA HCP clusters deployed in isolated AWS accounts with no outbound internet connectivity. All container images are served from a mirrored ECR registry inside the ZE account.

    CodeBuild Mirror Jobs¶

    Job Description
    ocp-mirror-2 Core OCP release images
    ocp-mirror-3 Additional operator images
    ocp-mirror-4 RHCOS + machine images
    ocp-mirror-5–8 Layered product images

    Mirror jobs run on a schedule and on demand when a new version needs to be published. They pull from Red Hat registries (with internet access) and push into the ZE root ECR.

    Required VPC Endpoints¶

    Zero egress clusters require specific AWS PrivateLink endpoints. Without these, the cluster cannot function:

    Endpoint Type Required For
    com.amazonaws.REGION.sts Interface IAM/IRSA token exchange
    com.amazonaws.REGION.ecr.api Interface ECR API calls
    com.amazonaws.REGION.ecr.dkr Interface ECR container pulls
    com.amazonaws.REGION.s3 Gateway S3 access (RHCOS ignition, etcd backups)

    S3 must be a Gateway endpoint

    S3 uses a Gateway-type endpoint, not an Interface-type. A common misconfiguration is setting S3 as Interface, which breaks ignition delivery to workers.

    ECR Credential Refresh CronJob¶

    ECR tokens expire every 12 hours. A CronJob in kube-system on each ZE cluster refreshes the pull secret:

    # Check the CronJob is present and recent
oc get cronjob -n kube-system | grep ecr

# Check the last job run
oc get jobs -n kube-system | grep ecr

# Check the last job's logs
oc logs -n kube-system job/ecr-credentials-refresh-XXXXX

    If the CronJob fails and the token expires, new nodes cannot pull images and MachineConfig rollouts stall.

    Insights Operator (Disabled by Design)¶

    The Insights Operator is deliberately disabled on Zero Egress clusters because it requires outbound internet connectivity to console.redhat.com.

    # Verify Insights Operator is disabled
oc get clusteroperator insights
# STATUS: Available, Progressing: False, Degraded: False
# Conditions should show "Disabled" in message

# Check the HostedCluster annotation
oc get hostedcluster $CLUSTER_NAME -n $HC_NS \
  -o jsonpath='{.metadata.annotations.hypershift\.openshift\.io/insights-operator}'

    Do not attempt to enable Insights Operator on ZE clusters — it will CrashLoop without internet access.

    Accessing a Zero Egress Cluster¶

    Because ZE clusters have no public endpoints, access requires backplane and PrivateLink:

    # Login via backplane (uses PrivateLink/VPCE chain)
ocm backplane login $CLUSTER_ID

# Verify private connectivity
oc cluster-info

    If backplane access fails: 1. Check that PrivateLink VPC endpoint exists and is available 2. Check Transit Gateway route table entries 3. Confirm the cluster's hostedcluster.status.kubeconfig is populated

    Troubleshooting Zero Egress Clusters¶

    Image Pull Failures¶

    # On the guest cluster
oc get pods -A | grep -E "ImagePull|ErrImagePull"

# Check which registry images are being pulled from
oc get pods -n NAMESPACE POD_NAME -o yaml | grep -i image

# Should be ECR endpoints (*.dkr.ecr.*.amazonaws.com), not quay.io

    If pulling from quay.io: The imageContentSourcePolicy (ICSP) or ImageDigestMirrorSet is misconfigured. 

    oc get imagecontentsourcepolicy
oc get imagedigestmirrorset

    If ECR pull fails: 

    # Check VPC endpoints exist
aws ec2 describe-vpc-endpoints --filters "Name=service-name,Values=*ecr*"

# Check ECR token is valid (less than 12h old)
oc get secret pull-secret -n openshift-config -o jsonpath='{.data.\.dockerconfigjson}' \
  | base64 -d | jq '.auths | keys'

    Mirroring Verification¶

    # Check if an image exists in the ZE ECR
aws ecr describe-images \
  --registry-id 135808946024 \
  --repository-name openshift/release \
  --image-ids imageTag=4.17.5-x86_64

# List recently pushed tags
aws ecr describe-images \
  --registry-id 135808946024 \
  --repository-name openshift/release \
  --query 'sort_by(imageDetails, &imagePushedAt)[-5:].[imageTags[0],imagePushedAt]'

    Cluster Install Stuck at Workers¶

    Workers can't pull images → MachineConfig can't complete → install stalls:

    1. Check VPC endpoint for ecr.dkr (Interface) — must be available
    2. Check VPC endpoint for s3 (Gateway) — must be in route table
    3. Check ECR cross-account replication completed: 
      aws ecr describe-images --registry-id $CHILD_ACCOUNT_ID --repository-name openshift/release
    4. Check CRI-O logs on a worker node (via SSM): 
      osdctl hcp worker-log $CLUSTER_ID $NODE_NAME
